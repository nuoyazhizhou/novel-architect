## C1 · 协议学露出（思想霸权进度）
- **FAIL**：整章无任何协议学工具/论文/白皮书露出，林枫纯靠情节或武力推进。
- **WARN**：仅口头提及「协议」「系统」等词，无具体论文/工具/白皮书动作。
- **PASS**：出现具体协议学载体——信息带宽、认证中心竞争、去中介化、跨期终局性、特权环 Ring 隔离、PDCA、看板、甘特图、流程图、SWOT、思维导图、模拟项目教学(PVP)、四员下乡、白话文基建、公差接口、标准化，或林枫发表/引用某部著作。

## C2 · 先知剧透 vs 结构推演
- **FAIL**：林枫以「我知道 19XX 年会怎样」式跳大神直接剧透具体历史日期/事件，且无推演过程。
- **WARN**：剧透与推演混杂，读者能感到是开天眼。
- **PASS**：林枫通过现有数据/制度安排做出可证伪的推演（如「按工业链转移模型，德国复苏将冲击中国市场」），引导而非宣告。

## C3 · 时代物理阻抗（机械降神）
- **FAIL**：出现 1920–1940s 不可能存在的能力/产能而无铺垫（如凭空原子弹、现代计算机、无限产能），且非「降维十年科研绝密训令」框架内的长周期预研。
- **WARN**：技术细节模糊到可质疑（如「很快造出」但无时间/资源交代）。
- **PASS**：尊重电力/物流/机床/通信约束，超时代技术有「提前预研/抄底专家/技术移植」的明确来历。

## C4 · 对齐时间线总表当前幕
- **FAIL**：违反当前幕「绝对禁止」项（如本幕要求 1931 反杀关东军却写成被动挨打；要求 1927 物理整合国共建南京联合政府却写成苏联养蛊成功）。
- **WARN**：未体现当前幕「必须触发」项（如该幕应抄底德国专家/收割佛罗里达却完全没提）。
- **PASS**：本章事件、产出、扰动与总表当前幕锚点一致。

## C5 · 历史引力检测（最关键）
- **FAIL**：林枫沦为旁观者/小兵/抄作业者/被动目击者——章节主线由历史事件而非林枫的文明格式化动作驱动。
- **WARN**：林枫有动作但被动响应历史，缺乏议题设置者主动性。
- **PASS**：林枫以议题设置者身份主动施动（发表论文设定议程、用管理工具重组基层、用科技树降维），历史被他牵引。

## C6 · 二简字式压缩过头
- **FAIL**：把复杂社会改造简化为「推行拼音/简体字/一句口号」式解法，违背 `案例02_二简字` 的 hash 碰撞警示（降低接入成本的同时抬高了识别成本）。
- **WARN**：用口号/标语替代机制设计，或文字改革缺乏防碰撞考量。
- **PASS**：涉及文字/制度改造时体现「识别成本不升、解码成本真降」的协议学审慎，或以二简字为反面教材。
- **SKIP（大纲/细纲模式）**：当文档被识别为大纲/细纲（`--outline` 标记、文件头含 `<!-- lint:outline -->`、或文件名含「细纲/大纲/任务/幕」），本项跳过——「提出…口号」「农村宣传标语」属正常规划词，不应误伤。

## C7 · 爽点偏移
- **FAIL**：主爽点变成江湖暗杀、地摊打仗、纯武力碾压，而非「高维协议降维 / 论文武器库 / 制度 CA 竞争」的硬核科技官僚爽点。
- **WARN**：硬核爽点与暴力爽点并存，主次不清。
- **PASS**：爽点来自协议学武器的降维打击、论文/白皮书的思想霸权、制度认证中心的竞争。

## C8 · 八大驱动工具落地
- **FAIL**：全章无任何八大驱动工具或基层微观剩余（喝开水/堆肥/省柴灶/锅驼机）痕迹，叙事与「技术官僚改造」脱节。
- **WARN**：仅一处点缀式提及，未与情节融合。
- **PASS**：PDCA/看板/甘特图/流程图/SWOT/思维导图/PVP/四员下乡 与基层微观剩余在叙事中自然落地，支撑「民心所向」。

## C9 · 概念溯源闸门（公理前置 / Concept Genesis Gate）
- **核心隐喻**：林枫的《社会系统协议学》用了大量 **1950–2020 年代才被人类发明/命名**的名词（特权环 Ring、去中介化、认证中心、跨期终局性、脑裂、技术债、协议栈、Syscall、Agent 博弈、TCP/UDP、API、哈希、PDCA、看板、MVP）。若 1920s 叙事里直接甩这些词，等于「空降术语 / 机械降神」。**这就像证明一个猜想——不先完成前置引理（用 1920s 语言铺一层脚手架），别人（读者/剧中人）无从理解你的逻辑来源。**
- **FAIL（P0·严重空降）**：出现 B 类未来名词，且全文连任何 1920s 脚手架关键词与解释标记都没有——纯现代术语轰炸，无任何铺垫信号。须先补类比引入再点名。
- **WARN（P1·疑似空降）**：出现 B 类未来名词，但该名词自身的脚手架关键词未命中（也无解释标记）。建议在本章内先用 1920s 现象/痛点做类比，或加「即 / 好比 / 如同 / 说白了 / 打个比方」等解释标记。
- **PASS**：B 类名词出现时，已命中其 1920s 脚手架关键词，或出现「即 / 好比 / 如同 / 说白了 / 打个比方」等解释标记（视为已做类比引入）。
- **底座与清单**：名词 → 脚手架 → 点名幕次 → 前置依赖，见 `references/concept-genesis.md` 的 B 类登记表（与 `lint_chapter.py` 的 `CONCEPT_GENESIS` 字典同步）。跨章前置依赖（如用「脑裂」须先铺垫「单一权威」）由哨兵人工核验。
- **跨章状态账本（State Ledger）**：概念在某章完成脚手架/解释铺垫后，可运行 `python lint_chapter.py <章.md> --update-ledger` 将其记入 `插件根/.local/axiom_ledger.json`。**后序章节引用该概念时**，只要 ledger 中已解锁，C9 直接判 PASS，不再强制本章内重复脚手架（避免每章都打一遍长比方）。重置账本只需删除该 json 文件。

## C10 · 文笔质检（去 AI 味 / 代入感 / Show-don't-tell）
- **WARN（P1·机器初判）**：AI 味套路词密度偏高（约 ≥6 处/千字）或告知式说理词（"这说明/意味着/众所周知/不难看出…"）≥3 处。机器只做**密度告警**，是否真 AI 味、如何改写，由 **文笔·修辞（修辞）agent 终判**。
- **PASS**：AI 味词密度正常，未见明显告知式说理堆砌。
- **说明**：本项**永不机判 FAIL**——文笔是主观维度，硬打回会误杀有风格的写作；它只在密度异常时提请修辞 agent 介入。视角跳切、感官/动作锚点、对话比等细项由修辞 agent 人审。

## 门禁
- 任一 **FAIL（P0）** → 打回重写，不得进入下一章（C1/C3/C5/C6/C9 可触发）。
- **WARN（P1）** → 应改，可附条件通过（C2/C7/C8/C10 通常为 WARN）。
- 全部 PASS → 转史官做因果审计（C4 已在史官处二次核验）→ 文笔·修辞终判 C10。
